# Native stability and subtitle preview 0.4.10

Updated 2026-10-06. Version **0.4.10 / 1000050**. This release remains a preview, with physical acceptance and production tasks outstanding.

## Changes

- Preserve the original screen implementations, layouts, fonts, images loader, profile screens and native video player. No replacement remote WebView video page was added. The existing bundled local libass overlay remains the subtitle renderer.
- Home keeps coherent pages during background refresh, rejects severely incomplete replacement feeds and avoids repeated collection cards. When ani.pm collections fail, AniList supplies genre/movie/trending/season metadata with truthful labels. View All has a paginated fallback preserving the collection and offset. Related titles also retain an actual supported genre when their primary provider fails.
- Search appends stable cards even if a later page reveals a prequel. Known recent franchise relationships are reused to reduce title-click request bursts. Existing verified season/source-ID mapping and 16:9 image cropping remain.
- Public metadata uses shared in-flight requests, two-minute discovery freshness, bounded Retry-After cooldowns, temporary-error last-good fallback and an atomic private public-metadata cache (seven-day maximum, 96 records, 24 MiB). A removed title's HTTP 404 is not hidden by a stale success. Sessions, profile state and media URLs are not stored in this cache.
- If episode availability fails, retain loaded real episodes or display a valid metadata-only original title page with a temporary-unavailability notice. Metadata-only counts are not converted into invented playable episodes, audio or subtitles. Unknown availability retries after a short interval.
- Fix the reproduced main-thread `NoSuchElementException` in the original `ShowContentInteractor`: empty up-next responses now return HTTP 204 rather than HTTP 200 with an empty list. The original controller handles this as no content. This also covers the last episode's missing successor without modifying original screen code.
- Initialize the original account restriction observer on all authenticated routes, including direct My Lists entry. Clear the obsolete email-confirmation reminder only when the actual Supabase identity has `email_confirmed_at`. The blank “Not now” banner was reproduced before the fix and absent from My Lists afterward.
- Actual selected-profile playheads now populate original Continue Watching and History models, with recent-first paging, grouped-series deduplication and deletion. Save cached source/title metadata with progress so recent rows can reconstruct after restart without refetching every series. Batch validation is atomic, including oversized numeric IDs. Existing Supabase profile snapshots persist this progress; fresh-device restore/conflict acceptance is still pending.
- Real VTT, SRT and ASS/SSA tracks reach the retained language selector/renderer. Separate cues use bold white text, black outline and bottom-center alignment, preserving timing, Unicode and line breaks. Malformed individual cues do not discard valid dialogue. Converted buffers/track registry are bounded. Complex source positioning/karaoke is simplified. Explicit matching hard subs remain preferred; the app does not burn subtitles into video or restyle actual burned-in text.
- Playback resolution coalesces duplicate requests by episode and subtitle preference. Offline subtitle preparation prioritizes the selected language, fetches tracks concurrently with a deadline, and skips failed optional tracks without advertising them as saved. Failure of the selected track still aborts preparation. Download authorization is tied to the current owner. Completion/offline/delete/isolation still need acceptance.
