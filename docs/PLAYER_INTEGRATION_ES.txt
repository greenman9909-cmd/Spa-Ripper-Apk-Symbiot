3. CÓMO RESOLVEMOS VÍDEO EN ANDROID

NativePlayback.watchBundle(): obtiene ssub/sdub según audio.
NativePlayback.resolveSource(): evalúa hasta 8 fuentes; preferencia por hard sub
del idioma seleccionado, después fuente sin hard sub o con el mismo idioma.
NativePlayback.directSource(): admite type=hls solo con HTTPS pública y contrato
de referer que coincide con https://megaplay.buzz/.

En fuentes type=embed de MegaPlay, el código existente:
1) Valida host exactamente megaplay.buzz y ruta /stream/.
2) Lee HTML de esa ruta sin ejecutarlo, extrae data-id numérico acotado.
3) Consulta https://megaplay.buzz/stream/getSources?id={dataId}.
4) NativePlayback.decodeSources() decodifica el campo enc del contrato existente.
5) Lee decoded.file y verifica HTTPS y manifiesto que empieza con #EXTM3U.
6) Agrega pistas del bundle, sources.tracks y decoded.tracks.
7) Usa hardsub_locale/hardsubLocale declarados y rangos reales disponibles.

Portar ese adaptador al BACKEND cuando el uso esté permitido por la fuente;
no ejecutar HTML del proveedor, no iframe, no window.open ni navegación publicitaria.
decodeSources() contiene el contrato de cifrado/padding concreto del proveedor:
referirse al código revisado, no tratarlo como estándar HLS ni usarlo para saltar
DRM, cuentas, pagos o restricciones de acceso. Ese contrato externo puede cambiar.

Cabeceras de media que hoy usa la APK:
Referer: https://megaplay.buzz/
User-Agent: Mozilla/5.0 (Linux; Android 14) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Mobile Safari/537.36
En la petición getSources, la APK usa como Referer la URL embed correspondiente.
Estas cabeceras no se pueden copiar libremente al navegador para simular Android.
Una URL extraída válida en Android puede fallar en web por CORS/Referer/caducidad.

4. DECISIÓN NECESARIA: DIRECTO O ENTREGA BACKEND

La prueba decisiva ocurre desde el DOMINIO REAL de tu web:
- Master, variantes, segmentos, pistas y recursos necesarios permiten CORS y las
  condiciones de acceso -> se puede reproducir directo.
- Fuente permite entrega por servidor y exige cabeceras no disponibles en navegador
  -> backend controlado para resolver y entregar media.
- Fuente no permite ese uso -> no declarar una reproducción garantizada; usar una
  fuente compatible y autorizada. No usar el backend para eludir una prohibición.

Devolver una URL del resolver al cliente no arregla las peticiones de segmentos.
Si se necesita relay, reescribir el árbol HLS completo con parser: master, variantes,
EXT-X-MEDIA, mapas/init, segmentos, claves legítimas, URI relativas y querystrings.
Conservar Range/206/Content-Range cuando proceda, streaming/backpressure/cancelación,
timeouts, cuotas y límites de tamaño. No descargar la película entera a RAM.
No transmitir cookies/Authorization de tu usuario al proveedor.

El endpoint de relay debe aceptar opaqueId emitido por tu backend, no ?url=cualquiera.
Validar HTTPS, hosts explícitos aprobados y DNS/IP públicos en cada salto; impedir
SSRF, redirecciones a redes privadas y puertos arbitrarios. Validar de nuevo en
fetch; no basta una expresión regular ni publicHttps() de la clase Android.
No publicar URLs firmadas, tokens ni payloads completos en logs.
Resolución/bundles son temporales: cache limitada en RAM, no catálogo persistente.

GitHub Pages no ejecuta ese backend. Puedes mantener tu web actual y añadirle una
API aparte si hace falta. Elegir hosting por streaming, tiempos y coste de egress;
no asumir que una función gratuita soporta la entrega de vídeos largos.

6. HARD SUBS Y SOFT SUBS: POLÍTICA EXACTA

Preferir hard subs para el idioma elegido, permitir pistas separadas.
Hard sub significa texto grabado en los píxeles. No se cambia su fuente, tamaño,
idioma ni posición con CSS, y no se puede desactivar sin otra copia de vídeo.
Lo que implementamos para letras grandes blancas es ESTILO DE PISTAS SEPARADAS;
la APK no quema ni traduce nuevos subtítulos en el vídeo.

Algoritmo:
1) Normalizar idioma solicitado y locales declarados.
2) Fuente con hardsub locale exactamente coincidente -> preferida.
3) Si no, fuente sin hard sub + pista de ese idioma -> preferida.
4) Si no, ofrecer idiomas reales o None; no fallback silencioso a otro idioma.
5) Fuente con hard sub de otro idioma no debe presentarse como traducción solicitada.
Solo marcar hard sub con hardsub_locale/hardsubLocale explícito; audio=sub no prueba
que haya texto grabado. La metadata ausente es desconocida, no prueba universal
de que los píxeles carezcan de subtítulos; documentar y comprobar visualmente.

Track mapping desde el proveedor:
URL: file, si falta url. Excluir kind=thumbnails.
Formato: format, con extensión de URL como alternativa; aceptar VTT/SRT/ASS/SSA.
Locale: language -> srclang -> locale; normalizar '_' a '-'. Si und/vacío, usar
label real. Spanish + Latin/Latam -> es-419; Portuguese + Brazil -> pt-BR.
Español genérico se normaliza es-ES en el adaptador actual; conservar esta regla
explícita, no asegurar dialecto auditado por etiqueta sola. zh-Hant -> zh-TW,
zh-Hans -> zh-CN. No convertir es-419 en es-ES ni eliminar Unicode.
Mostrar idiomas del episodio actual, no una lista universal de 35 idiomas.
No poner nombres de doblajes porque exista una pista de subtítulos en ese idioma.

NativeSubtitles registra URLs appassets.androidplatform.net para libass Android.
NO usarlas en tu web. Servir pista convertida por tu API o usar URL real compatible
con CORS. Content-Type: text/vtt; charset=utf-8 para salida WebVTT.
Convertir SRT tiempos con coma y ASS/SSA a cues temporizados si se usa overlay;
esto simplifica karaoke/posicionamiento/estilos ASS complejos. Para conservar ASS
completo, elegir renderer mantenido y probar fuentes/WASM/fullscreen aparte.
Rechazar HTML/errores, tiempos NaN, end<=start, cues vacíos y payloads excesivos.
NativeSubtitles usa límite 1 MiB. No renderizar texto remoto mediante innerHTML.

import Hls from 'hls.js';
const video = document.querySelector('#web-video');
const message = document.querySelector('#player-message');
let hls = null, pending = null, generation = 0;
function releaseVideo() {
  video.pause();
  hls?.destroy(); hls = null;
  video.removeAttribute('src'); video.load();
  // Aquí retirar tracks/listeners/cues del episodio anterior en tu componente.
}
export async function openEpisode(request) {
  const current = ++generation;
  pending?.abort();
  pending = new AbortController();
  const controller = pending;
  const deadline = setTimeout(() => controller.abort(), 30000);
  releaseVideo();
  message.textContent = 'Preparando el episodio…';
  try {
    const response = await fetch('/api/player/resolve', {
      method: 'POST', headers: {'Content-Type':'application/json'},
      credentials: 'same-origin', signal: controller.signal,
      body: JSON.stringify(request)
    });
    if (!response.ok) throw new Error('resolve');
    const result = await response.json();
    if (current !== generation) return;
    if (result.anilistId !== request.anilistId || result.episode !== request.episode ||
        result.audio !== request.audio || result.source?.type !== 'hls') {
      throw new Error('identity');
    }
    const url = new URL(result.source.url, location.href);
    // Validar aquí origen/hosts que tu API aprobó; backend valida también.
    if (url.protocol !== 'https:' && url.origin !== location.origin) throw new Error('url');
    if (Hls.isSupported()) {
      hls = new Hls();
      hls.on(Hls.Events.ERROR, (_event, data) => {
        if (current === generation && data.fatal) {
          releaseVideo();
          message.textContent = 'No se pudo reproducir. Reintenta este episodio.';
        }
      });
      hls.loadSource(url.href); hls.attachMedia(video);
    } else if (video.canPlayType('application/vnd.apple.mpegurl')) {
      video.src = url.href;
    } else {
      throw new Error('unsupported');
    }
    message.textContent = 'Pulsa reproducir.';
    // Montar selector/track elegido e intervalos reales a partir de result.
    // Autoplay puede bloquearse; mantener un botón Play visible y accesible.
  } catch (error) {
    if (current !== generation) return;
    releaseVideo();
    message.textContent = 'No se pudo preparar el episodio. Puedes reintentar.';
  } finally {
    clearTimeout(deadline);
  }
}
export function closePlayer() {
  ++generation; pending?.abort(); pending = null; releaseVideo();
}

Si la API está en otro dominio, ajustar URL, credentials y CORS de tu auth; no

Guardar progreso por usuario/perfil/ID/episodio/audio usando tu sistema existente;
no escribir en Supabase sin revisar schema compatible con la APK.

10. LÍMITES/ERRORES Y PRUEBAS DEL PLAYER

Cache APK de referencia: bundle 45 s, errores 5 s, 16 entradas / 2 Mi caracteres;
resolución por asset+idioma 60 s. Son políticas iniciales, no permiso para mantener
una URL más allá de su expiración. Coalescer requests Play+Skip en un solo bundle.
Usar AbortController, cola/concurrencia limitada y bounded retry con Retry-After.
Un error de pista opcional no debe derribar el vídeo si el usuario acepta otro idioma;
si pidió una pista y falla, avisar claramente, no decir que está viendo español.

Pruebas antes de anunciar listo:
1. Frieren E1 sub: elegir ambos españoles reales, seek y sincronización visible.
2. Naruto E1: inglés/None, nada inventado; intro inválida no muestra Skip.
3. One Piece E1: vídeo avanza, se oye, carga segmentos y sobrevive fullscreen.
4. Hard sub del idioma solicitado solo con metadata y aceptación visual; doble
   overlay no aparece, y hard sub de otro idioma no se selecciona silenciosamente.
5. Cambiar rápido dos episodios: abort/identity impiden que gane una respuesta vieja.
6. 429, URL caduca, HTML 200, master bueno/segmento malo, subtítulo caído, sin audio
   solicitado: error localizado, reintento finito, sin volver a Home.
7. Repetir abrir/cerrar: no acumular HLS/listeners/conexiones/track nodes.
8. Chrome/Firefox desktop, Android y Safari/iPhone reales: CORS, fullscreen, cues,
   autoplay, controles, dimensiones 4:3 y 16:9, teclado y accesibilidad.
9. Confirmar que no se ejecutan scripts externos/embed, no hay window.open y no
   salta a Google. Esto no demuestra que el archivo no incluya publicidad propia.

No publicar tokens, cookies, contraseñas ni URLs temporales completas en fixtures.
